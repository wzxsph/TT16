# TT16 · TradeType 16 交易人格十六型

## 商业规划书：一次性付费解锁的社交传播型数字快消品

- **版本**：v1.0
- **日期**：2026-07-11
- **适用阶段**：OPC / 单人公司 / 极小团队早期验证
- **目标市场**：中国大陆中文互联网用户
- **商业化假设**：完成测试免费，支付 **¥4.9（对外可称“5 元”）** 解锁全部结果与完整报告
- **首发载体**：移动端 H5 网站
- **文档性质**：商业决策与执行规划，不构成法律、税务、金融或投资建议

> **战略定性**
>
> TT16 不是一款需要长期留存、订阅会员和社区运营的平台型产品，而是一款依靠话题、好奇心和低价冲动消费完成变现的数字快消品。
>
> 它的目标不是“把一个用户经营三年”，而是“在一次 3—5 分钟的体验中，把低成本流量转化为 4.9 元订单，并在流量窗口结束前实现正现金回报”。

## 0. 核心决策摘要

本商业规划书采用以下六项确定性决策。

| 决策项 | TT16 的选择 | 不做什么 |
|---|---|---|
| 产品性质 | 一次性、低客单价、社交传播型数字内容商品 | 不做长期平台，不追求月活与留存 |
| 收费模式 | 测试过程免费，结果全部锁定，¥4.9 一次性解锁 | 不做订阅、不做多档会员、不做复杂增购 |
| 首发载体 | 移动端 H5 网站 | 首发不同时开发小程序、App 和桌面客户端 |
| 核心交付 | 16 型交易人格结果、四维分数、场景化报告、结果卡、PDF/长图 | 不接交易账户，不做实盘分析，不荐股 |
| 流量策略 | 自有内容、自然热点、小型创作者分成、社群传播 | 验证前不买大规模信息流，不付高额 KOL 坑位费 |
| 成功标准 | 收回现金成本、订单链路稳定、用户觉得“值 5 元” | 不以融资故事、长期壁垒或用户规模作为首期目标 |

### 0.1 一句话商业模型

> **用一个有传播感的“股票版人格测试”获得低成本流量，用答题后的好奇心和时间投入推动 4.9 元冲动付费，用模板化但有个性化感知的报告完成交付。**

### 0.2 首期唯一需要验证的问题

> 一个已经完成 TT16 测试的用户，是否愿意支付 4.9 元，知道自己是哪一种交易人格并查看完整报告？

首期不同时验证会员、社区、券商合作、交易日记、AI 助手等其他命题。

## 1. 执行摘要

### 1.1 项目概览

| 项目 | 规划 |
|---|---|
| 品牌 | TT16 / TradeType 16 / 交易人格十六型 |
| 产品形态 | 16—20 道情境题 + 付费墙 + 在线报告 + PDF/长图 |
| 目标用户 | 18 岁以上、接触股票或财经内容、习惯在社交平台表达身份的中文用户 |
| 主要动机 | 好奇、自我确认、身份标签、社交谈资 |
| 标准价格 | ¥4.9，一次购买，当前报告永久查看 |
| 核心渠道 | 小红书、B 站、抖音、微博、视频号、公众号、投资社群、朋友圈 |
| 主要成本 | 视觉、开发、支付与备案、内容、服务器、渠道分成、售后 |
| 生命周期 | 单次流量活动可按 2—8 周管理；流量结束后允许项目自然停止 |
| 北极星指标 | 每 1,000 个落地页访客产生的贡献毛利 |
| 关键约束 | 必须有合法经营主体、合规收款路径、明确售后规则与金融内容边界 |

### 1.2 商业逻辑

TT16 的购买不是严格意义上的“理性投资决策”。用户购买的主要是四种感受：

1. **好奇闭环**：我到底是哪一种？
2. **身份标签**：我可以用一个四字母代码和中文称号描述自己。
3. **自我确认**：报告中有几句话让人产生“它确实在说我”的感觉。
4. **社交素材**：结果卡可以成为朋友圈、群聊或内容平台的谈资。

因此，首期报告不需要提供专业投顾价值，也不需要真正改善用户的收益率。它必须做到的是：

- 用户在付款前知道自己买什么；
- 用户付款后立刻得到结果；
- 16 类报告有明显差异；
- 至少有 3—5 处与答题结果强相关的具体描述；
- 视觉质量与文案质量足以让多数用户认为“4.9 元不亏”；
- 不涉及具体证券选择、买卖时点或收益承诺。

### 1.3 本项目不追求的目标

TT16 首期不追求：

- 用户次日、七日或三十日留存；
- 订阅收入；
- 社区网络效应；
- 交易数据壁垒；
- 券商 B 端销售；
- 心理学测量资质；
- 投资者适当性评估；
- “国内第一”“最科学”“准确率 98%”等无法证明的宣传。

这不是能力不足，而是主动限制范围，以符合 OPC 的资金、时间和运营能力。

## 2. 项目背景与机会判断

### 2.1 市场信号

2026 年 SBTI 依靠短答题、荒诞标签和结果分享出现广泛传播，主流媒体将其视为一种以幽默、自嘲和社交认同为核心的娱乐测试现象。[^1][^2] 同期也已经出现股票 GBTI 等娱乐向交易风格测试，且公开代码表明这类产品的开发门槛并不高。[^3]

这些信号说明：

- 用户对“人格标签 + 结果卡”仍有兴趣；
- 股票、交易与人格结合并非空白概念；
- 技术不是主要壁垒；
- 真正稀缺的是传播时机、视觉包装、文案和低成本流量；
- 免费同类产品会对 TT16 的付费产生直接压力。

### 2.2 机会窗口

TT16 的窗口不在于创造一个全新品类，而在于把已有需求包装成一款更像“商品”的产品：

- 品牌比临时生成的 GBTI 页面更完整；
- 16 种人格拥有统一视觉系统；
- 报告比免费结果页更精美；
- 价格低到接近冲动消费；
- 付费前展示明确样例，降低不确定性；
- 用股票用户熟悉的“追高、踏空、死扛、满仓、财报、题材、止损”等情境制造共鸣。

### 2.3 市场本质

本项目不适合用“人格测试市场规模多少亿元”来论证。针对“付费股票人格报告”这一极窄品类，没有足够可靠的公开市场数据，强行估算 TAM 容易制造虚假确定性。

更合理的是采用**自下而上的可触达市场模型**：

```text
可触达访客 = 各渠道内容曝光 × 链接点击率
预计订单 = 可触达访客 × 开始率 × 完成率 × 支付墙转化率
预计收入 = 预计订单 × 客单价
```

换言之，TT16 的市场大小不是“中国有多少股民”，而是：

> 在一个具体流量窗口中，我们能以多低的成本让多少人进入页面，并让其中多少人在完成测试后付款。

### 2.4 机会与限制同时存在

| 有利条件 | 不利条件 |
|---|---|
| 人格测试天然具备身份表达与讨论属性 | 同类概念易复制，免费替代品多 |
| 股票情绪场景丰富，容易写出共鸣文案 | 用户对“付费才能看结果”可能反感 |
| 4.9 元决策成本低 | 低客单价意味着无法承受高获客成本 |
| 报告可模板化，边际交付成本低 | 一次性产品几乎没有复购和留存 |
| H5 可以快速上线和迭代 | 收款、备案、退款与平台审核并不等于零成本 |

结论是：**产品可以很简单，但流量和收款不能被想当然。**

## 3. 竞品与替代方案

### 3.1 竞争类别

| 类别 | 代表形态 | 用户获得什么 | 对 TT16 的威胁 |
|---|---|---|---|
| 免费病毒式测试 | SBTI、各类热点人格测试 | 免费身份标签与分享卡 | 用户会质疑“为什么你的结果要收费” |
| 股票人格测试 | GBTI、投资风格测试、交易人格内容 | 股票语境下的娱乐画像 | 概念不独占，题目和人格名易被复制 |
| 传统付费人格报告 | MBTI 类报告、职业/情感测试 | 更长、更正式的个性解释 | 教育了用户为“了解自己”付款 |
| 券商风险测评 | 保守、稳健、进取分类 | 风险等级与合规流程 | 更权威，但娱乐性和分享性弱 |
| 免费 AI 生成 | 用户让通用 AI 分析投资风格 | 快速、个性化、几乎免费 | 降低普通文字报告的稀缺性 |

### 3.2 TT16 的差异化

TT16 不应宣传“我们是第一个股票人格测试”。更可信的差异化是：

1. **完整品牌**：TT16 的命名、代码、16 类角色、视觉和文案统一。
2. **交易场景感**：问题和报告围绕真实股民语言，而不是把普通 MBTI 生硬换词。
3. **付费商品感**：购买前能看到样例、目录和交付格式，付款后立即获得完整在线报告与结果卡。
4. **低价格**：把购买行为控制在“少一次饮料”的心理区间。
5. **可传播结果**：即使结果付费，付款用户仍可生成高辨识度卡片。
6. **透明娱乐定位**：不伪装成心理诊断或投资咨询。

### 3.3 不建立虚假壁垒

TT16 首期没有长期技术壁垒，也不需要假装有。

它的短期竞争力来自：

- 上线速度；
- 视觉完成度；
- 人格命名和文案；
- 渠道与发布时间；
- 支付转化页面；
- 低成本复用的产品模板。

这是一门**执行和分发生意**，不是一门深技术生意。

## 4. 目标用户与购买心理

### 4.1 核心用户

| 用户类型 | 特征 | 购买触发 | 主要顾虑 |
|---|---|---|---|
| 社交型股民 | 经常在群聊、小红书、微博或社区讨论行情 | 想知道自己是哪一型，并和朋友比较 | 付费才看结果是否被套路 |
| 新手投资者 | 入市时间不长，交易方法摇摆 | 想获得简单清晰的自我解释 | 报告会不会全是废话 |
| 年轻财经内容用户 | 不一定重度交易，但关注股票、基金和财经梗 | 对新鲜概念和精美视觉敏感 | 5 元是否值得、支付是否麻烦 |
| 情绪受挫用户 | 刚经历亏损、踏空、卖飞或追高 | 想从人格角度解释自己的行为 | 报告会不会说教或羞辱自己 |

### 4.2 非核心用户

首期不为以下用户优化：

- 寻找具体买卖建议的人；
- 专业机构交易员或量化团队；
- 希望得到心理学正式评估的人；
- 不接触股票、基金或财经内容的人；
- 未满 18 周岁的用户；
- 对任何付费测试天然排斥的人。

### 4.3 Jobs to Be Done

用户并不是在“购买一份 PDF”，而是在完成以下任务：

> 当我看到一个与炒股有关的人格测试时，我想快速知道自己属于哪种交易者，并获得几句能解释我过去行为的话，这样我可以满足好奇、确认自我，并把结果分享给朋友。

### 4.4 付款心理链路

```text
看到有趣概念
→ 觉得题目像真实经历
→ 连续完成答题
→ 产生“结果已经属于我”的感觉
→ 看见报告已生成但未揭晓
→ 4.9 元价格显得很低
→ 付款完成好奇闭环
```

这里存在“已投入时间”的心理作用，但产品不能依赖欺骗。价格必须在用户开始前明确展示，避免用户做完后才突然发现收费。

## 5. 品牌定位与传播表达

### 5.1 品牌名称

- **英文品牌**：TT16 / TradeType 16
- **中文品牌**：交易人格十六型
- **产品简称**：TT16

### 5.2 定位语

> **3 分钟，测出你在股市里的本能反应。**

备选：

- 你研究的是股票，还是市场正在研究你？
- 同样一根大阴线，16 种人格会做出 16 种选择。
- 测测你在追高、踏空和暴跌时，究竟会变成谁。

### 5.3 品牌语气

| 应该 | 不应该 |
|---|---|
| 有梗、具体、带一点自嘲 | 侮辱用户、把用户叫“韭菜废物” |
| 说人话，使用真实交易场景 | 堆砌行为金融术语 |
| 允许矛盾和反差 | 宣称一种人格比其他人格更赚钱 |
| 明确是娱乐测试 | 冒充专业心理测评、券商风评或投顾服务 |
| 用“可能、倾向、常见” | 用“你一定、你注定、准确率 98%” |

### 5.4 品牌承诺

> 花 4.9 元，你会得到一个明确的人格身份、一份看得懂的交易行为报告和一张值得保存的结果卡。

不承诺：

- 帮助盈利；
- 提高胜率；
- 推荐策略或股票；
- 判断风险承受能力；
- 提供心理诊断。

### 6.1 商业模式画布

| 模块 | TT16 规划 |
|---|---|
| 客户细分 | 年轻股民、财经内容用户、社交表达型投资者 |

### 6.2 收入结构

首期只保留一个商品：

| 商品 | 售价 | 交付 | 购买次数 |
|---|---:|---|---|
| TT16 完整交易人格报告 | ¥4.9 | 在线报告 + 结果卡 + PDF/长图 | 单次 |

不设置：

- 免费基础结果；
- 9.9 元高级版；
- 19.9 元专业版；
- 月度订阅；
- 年度会员；
- 付费复测；
- 交易建议增购。

单 SKU 的好处是决策简单、开发简单、数据口径简单。

### 6.3 生命周期

TT16 可以按照“数字快闪商品”管理：

1. 制作期；
2. 预热期；
3. 集中发布期；
4. 流量衰减期；
5. 长尾自动销售期；
6. 停止维护或归档。

项目自然结束不是失败。只要累计贡献毛利覆盖现金成本并达到预设回报，项目即成立。

### 6.4 长期价值的最低保留

虽然不做平台，仍应保留可复用底层：

- 问卷组件；
- 计分引擎；
- 付费墙；
- 订单回调；
- 报告模板；
- 分享卡生成；
- 渠道统计。

这不是为了把 TT16 做复杂，而是为了在它成功后能低成本复制下一款测试。

## 7. 产品商业化方案

### 7.1 用户完整链路

```text
渠道内容/朋友分享
→ 落地页
→ 明确看到“完整报告 ¥4.9”
→ 开始测试
→ 完成 16—20 道题
→ 结果生成动画
→ 硬付费墙：人格代码、名称、分数全部遮挡
→ 微信/支付宝等合规支付
→ 在线揭晓人格
→ 阅读完整报告
→ 保存 PDF/长图
→ 分享结果卡
```

### 7.2 落地页

落地页只承担四个任务：

1. 让用户理解这是“交易人格测试”；
2. 告诉用户大约需要多久；
3. 明确说明完整结果收费 4.9 元；
4. 让用户点击开始。

建议首屏：

> **你是哪一种交易人格？**
>
> 20 道真实股市场景题，测出你如何判断、持有、下注与执行。
>
> 测试免费完成｜完整结果与报告 ¥4.9
>
> `[开始测试]`

首屏下方展示：

- 四个测量维度；
- 3—4 张虚构示例人格卡；
- 一份示例报告的局部截图；
- 娱乐性质与非投资建议说明；
- 售后和交付说明。

### 7.3 测试长度

商业化 MVP 建议从原 PRD 的 32 题缩减为 **20 题**：

| 题目类型 | 数量 | 作用 |
|---|---:|---|
| 四个核心维度 | 16 | 每个维度 4 题，决定四字母代码 |
| 压力场景题 | 2 | 生成“暴跌反应”和“踏空反应”模块 |
| 一致性题 | 2 | 降低随意作答和明显矛盾 |
| 合计 | 20 | 目标 3—5 分钟完成 |

原因：

- 全结果锁定比免费结果更容易引发“我做了这么久还要付费”的抵触；
- 题目过长会降低支付墙到达量；
- 首期定位是娱乐型快消品，不需要伪装成严谨心理量表；
- 题目应优先保证场景感和阅读流畅，而不是追求研究论文级信度。

### 7.4 题目原则

- 一屏一题；
- 每题 2—4 个选项；
- 不出现明显“正确答案”；
- 使用具体场景而不是抽象自评；
- 避免让每个选项都很长；
- 允许用户直觉作答；
- 不询问资金规模、券商账号、持仓或收入；
- 不把结果包装成专业风险等级。

示例：

> 你买入一只股票后一周下跌 12%，公司没有新公告，你更接近哪种反应？
>
> A. 重新检查最初逻辑，逻辑没变就先不动
>
> B. 价格已经说明市场不认可，优先减仓观察
>
> C. 越跌越便宜，考虑加仓
>
> D. 先离场，等情绪稳定后再说

### 7.5 结果生成动画

答题提交后用 3—5 秒生成动画提升期待感：

- 正在分析你的决策锚点；
- 正在计算你的持仓耐心；
- 正在识别你的风险表达；
- 正在还原你的执行方式；
- TT16 报告已生成。

动画不得伪造“正在连接交易所”“扫描账户”等不存在的能力。

### 7.6 硬付费墙

用户未付款前不显示：

- 四字母代码；
- 中文人格名称；
- 四维百分比；
- 报告正文；
- 个性化结果卡。

可以显示：

- “你的报告已生成”；
- 一个被模糊的人格轮廓；
- 报告目录；
- 虚构示例报告；
- 本次购买价格；
- 交付内容；
- 售后规则；
- 娱乐测试与非投资建议说明。

推荐付费墙文案：

> **你的 TT16 已经生成**
>
> 解锁后立即获得：
>
> - 你的四字母人格代码与专属称号
> - 四项交易倾向分数
> - 牛市、暴跌和踏空时的典型反应
> - 3 个优势与 3 个高频交易 Bug
> - 专属结果卡和完整 PDF 报告
>
> **一次解锁 ¥4.9**
>
> `[立即查看我的 TT16]`

### 7.7 付款后的报告结构

报告以在线网页为主，PDF/长图为附加下载，控制在 6—8 个手机屏幕、约 1,200—1,800 个中文字。

| 屏幕 | 内容 |
|---|---|
| 1 | 人格代码、人格名称、主视觉、一句话 |
| 2 | 四维分数与简要解释 |
| 3 | 你的典型决策路径 |
| 4 | 牛市、暴跌、踏空时的表现 |
| 5 | 三个优势 |
| 6 | 三个高频交易 Bug |
| 7 | 压力下的人格变形与一句自我提醒 |
| 8 | 专属结果卡、免责声明、保存与分享 |

### 7.8 内容生产方式

首期不使用实时大模型自由生成报告。采用人工审核的模块化内容：

```text
完整报告
= 16 型核心模板
+ 4 个维度对应模块
+ 2 个压力场景模块
+ 1 组优势模块
+ 1 组风险模块
+ 1 句人格金句
```

建议内容占比：

- 50%—60%：该人格独有核心正文；
- 25%—35%：维度组合模块；
- 10%—20%：压力题和结果强度模块。

这样仍然是低成本模板报告，但不同人格之间不会只换一个名字。

### 7.9 “套话”的质量底线

允许：

> 你比起市场当下的反应，更愿意相信自己对公司和逻辑的理解。价格下跌时，你首先做的是重新解释信息，而不是立刻承认判断改变。

不允许：

> 你有时很果断，有时也会犹豫。你既希望赚钱，也害怕亏损。你在熟悉的人面前会更真实。

判断标准：

- 是否出现了交易特有的场景和语言；
- 不同人格互换报告后，用户是否仍能察觉差异；
- 每份报告是否至少有 3 个具体行为描述；
- 是否避免“谁都适用”的万能句占据主体。

### 7.10 分享设计

付款用户可生成：

- 标准结果卡；
- 朋友圈竖版卡；
- 小红书封面卡；
- 群聊横版卡。

结果卡包含：

- TT16；
- 四字母代码；
- 中文人格名；
- 一句金句；
- 四维简图；
- 测试二维码或短链；
- “娱乐测试，不构成投资建议”的小字。

未付款用户可以分享一张非结果型邀请卡：

> 我的 TT16 报告已经生成。你敢不敢也测一下？

这不能替代结果分享，但可减少硬付费墙对裂变的完全阻断。

### 7.11 订单恢复与交付

不强制注册，但必须支持：

- 支付成功自动跳转；
- 支付回调失败后的主动查询；
- 当前浏览器保留报告访问权；
- 订单号恢复；
- 客服按交易记录恢复；
- 重复付款识别和退款；
- PDF/长图下载失败时重新生成。

“产品简单”不能等于“付了钱看不到结果”。

## 8. 载体选择：网站还是微信小程序

### 8.1 结论

> **首发只做移动端 H5，不同时做微信小程序。**

### 8.2 选择 H5 的理由

| 维度 | H5 | 微信小程序 |
|---|---|---|
| 迭代速度 | 快，适合频繁改题目、文案和价格 | 提交与审核流程更重 |
| 多平台流量 | 小红书、B 站、微博、群聊、二维码均可进入 | 更依赖微信生态 |
| 开发范围 | 一个响应式前端即可 | 需要单独小程序端与平台配置 |
| 生命周期 | 适合热点结束后低成本保留或下线 | 长期维护和平台规则依赖更强 |
| 搜索与品牌 | 独立域名可积累内容和品牌 | 主要在微信内部 |
| 支付体验 | 需根据浏览器环境配置相应支付方式 | 微信内支付更顺滑 |

### 8.3 H5 不是“无门槛”

官方微信支付文档说明，H5 支付需开通相应权限并配置支付域名，域名必须完成 ICP 备案。[^4] 若页面主要在微信内打开，还需要根据实际环境配置合规的微信内支付路径。

因此，商业上线前必须解决：

- 合法经营主体；
- 可用的支付商户号；
- 域名与备案；
- 支付产品审核；
- 商品与服务类目匹配；
- 客服、退款和账务流程。

不得使用个人收款二维码代替正式订单系统，因为它无法稳定完成自动回调、订单恢复、退款和渠道结算，也可能带来账户与合规风险。

### 8.4 何时才考虑小程序

只有满足以下条件后再评估小程序：

- H5 已经产生稳定订单；
- 主要流量明确来自微信内；
- 监测到支付跳转或浏览器限制显著损害转化；
- 预期新增收益高于开发、审核和维护成本。

小程序不是首发必需品，也不应仅因为“看起来更像产品”而开发。

### 8.5 技术架构

首期采用最小架构：

```text
H5 前端
├── 落地页
├── 答题页
├── 付费墙
├── 在线报告
└── 分享卡生成

轻量后端
├── 匿名测试会话
├── 计分接口
├── 订单创建
├── 支付回调与主动查询
├── 报告访问令牌
├── 渠道归因
└── 基础数据看板
```

不开发：

- 用户社区；
- 消息系统；
- 实时行情；
- 交易账户连接；
- AI 对话；
- 复杂 CMS；
- 多租户机构后台。

## 9. 定价策略

### 9.1 首发价格

- 页面展示价：**¥4.9**
- 对外传播：**“不到 5 元”或“5 元解锁”**
- 购买权益：当前报告一次解锁、永久查看，不自动续费。

### 9.2 为什么不是免费

免费结果有利于传播，但不符合本项目“直接验证低价数字商品”的目标。硬付费墙可以更快回答用户是否愿意为好奇心付费，并让产品从活动页面直接变成现金流商品。

代价是自然分享量下降，因此必须依靠外部内容流量或付费用户的结果分享补足。

### 9.3 为什么从 4.9 元开始

- 决策门槛低；
- 用户不需要复杂比较；
- 即使报告偏娱乐，也较少产生高金额损失感；
- 有利于验证“付费意愿是否存在”。

但 4.9 元不一定是收入最优价格。最终应看：

> **每个到达支付墙的用户产生的收入，而不是单独看支付率。**

示例模型：

| 价格 | 假设支付率 | 每 100 个支付墙用户收入 |
|---:|---:|---:|
| ¥4.9 | 12% | ¥58.8 |
| ¥6.9 | 9% | ¥62.1 |
| ¥9.9 | 6% | ¥59.4 |

以上仅为示例，不是行业数据。

### 9.4 简单价格实验

无需开发复杂 A/B 系统。可以按时间或渠道顺序测试：

1. 前 500 个支付墙 UV：¥4.9；
2. 下一批 500 个支付墙 UV：¥6.9；
3. 比较支付墙收入/UV、退款率和投诉率；
4. 若差异不明显，保留更符合品牌定位的 ¥4.9。

首发对外统一使用 4.9 元，避免多个价格导致用户互相比较和产生不公平感。

### 9.5 不使用的促销方式

- 虚假倒计时；
- 永不结束的“今日最后一小时”；
- 虚构付款人数；
- 虚构用户评价；
- 先标高价再长期 0.5 折；
- 诱导分享才能退款；
- 默认勾选自动续费。

## 10. 流量与增长规划

### 10.1 核心原则

> **4.9 元模式首先是一门低成本流量生意。**

产品能承受的获客成本极低。首发顺序应为：

1. 自有账号和朋友圈；
2. 自然热点内容；
3. 投资群与校园/朋友社群；
4. 小型创作者分成；
5. 低额试投；
6. 数据证明后才考虑更大渠道。

### 10.2 渠道优先级

| 优先级 | 渠道 | 合作方式 | 原因 |
|---|---|---|---|
| P0 | 自有小红书/B站/视频号/微博 | 自制内容 | 无现金获客成本，可快速试错 |
| P0 | 朋友圈、微信群、投资社群 | 二维码、结果卡、群内互动 | 用户场景匹配，反馈快 |
| P1 | 小型财经/生活方式创作者 | 高比例分成或联名内容 | 固定坑位费低，愿意尝试新玩法 |
| P1 | 校园金融社团、模拟炒股群 | 群体测试、话题活动 | 触达集中、传播方便 |
| P2 | 中大型 KOL | 先小样本、后固定合作 | 价格高，低客单产品风险大 |
| 暂不 | 信息流广告 | 仅在单位经济验证后 | 4.9 元通常无法承受较高 CPC |

### 10.3 KOL 分成模型的现实问题

在基准漏斗下：

- 落地页开始率：60%；
- 完成率：70%；
- 支付墙转化率：10%；
- 价格：¥4.9。

每个落地页访客产生的毛收入约为：

```text
0.60 × 0.70 × 0.10 × ¥4.9 = ¥0.2058
```

若给创作者 30% 毛收入分成，则其每个落地页访客收入约为：

```text
¥0.2058 × 30% = ¥0.0617
```

这对多数创作者并不十分有吸引力。因此，纯分成合作可能需要：

- 40%—50% 的较高分成；
- 联名人格卡和专属内容；
- 快速结算；
- 高转化的精准受众；
- 或由 TT16 提供可直接发布的视频/图文素材。

不要在没有历史转化数据时支付高额固定坑位费。

### 10.4 渠道合作建议

| 合作类型 | 建议 |
|---|---|
| 自有流量 | 保留全部收入，优先验证产品本身 |
| 小创作者纯分成 | 可从退款后实收的 40% 起测试 |
| 小额固定费 + 分成 | 仅在对方历史内容质量和受众匹配时采用 |
| 中大型 KOL | 先用可追踪短链做小规模试发，再谈固定合作 |
| 社群主 | 给予专属人格分布截图、抽取免费码或较高分成 |

具体分成必须以实际税费、退款、支付成本和双方合同为准。

### 10.5 内容传播矩阵

围绕“同一场景，16 种人格不同反应”制作内容：

- 大盘暴跌时，16 型人格在做什么；
- 股票卖飞后，哪种人格最容易追回去；
- 研究派与信号派为什么永远吵不完；
- 哪种人格最爱把短线做成长线；
- 哪种人格嘴上分散、实际满仓；
- 连续盈利三次后，16 型会怎样膨胀；
- 一只股票三天涨 30%，你会怎么选；
- 财报前夜，16 型人格的真实内心；
- 牛市第一天和最后一天；
- “我不是不止损，我只是在等市场理解我”。

### 10.6 14 天传播节奏

| 时间 | 内容 |
|---|---|
| D-7 至 D-5 | 发布“你在股市里是哪种人”概念和四维预告 |
| D-4 至 D-2 | 公开 4—6 种代表人格，邀请用户猜自己类型 |
| D-1 | 小范围内测，收集真实结果卡和反馈 |
| D0 | 正式发布，集中在自有渠道和合作群同步上线 |
| D1—D3 | 发布用户结果、16 型场景梗、FAQ 和反馈 |
| D4—D7 | 发布争议话题、人格对比和创作者联动 |
| D8—D14 | 复用表现最好的内容，测试第二价格或第二付费墙文案 |

### 10.7 裂变的合理预期

由于结果全部锁定，非付费用户无法分享具体人格，TT16 的自然裂变能力会弱于免费测试。

因此，不把“用户自动裂变”写入必然假设。增长依赖：

- 外部内容持续供给；
- 付款用户结果卡；
- 非结果型邀请卡；
- 创作者联名；
- 热点窗口。

## 11. 漏斗、单位经济与盈亏模型

### 11.1 核心公式

```text
订单数 = 落地页访客 × 开始率 × 完成率 × 支付墙转化率
毛收入 = 订单数 × 价格
贡献收入 ≈ 毛收入 ×（1 - 支付成本 - 退款损失 - 渠道分成）
项目利润 = 贡献收入 - 固定现金成本 - 其他可变成本
```

实际财务核算应按支付服务商、渠道合同、税费和退款规则逐项计算，上式仅用于商业判断。

### 11.2 每 10,000 个落地页访客的收入情景

假设价格为 ¥4.9：

| 情景 | 开始率 | 完成率 | 支付墙转化率 | 订单数 | 毛收入 | 每访客毛收入 |
|---|---:|---:|---:|---:|---:|---:|
| 保守 | 45% | 60% | 5% | 135 | ¥661.50 | ¥0.066 |
| 基准 | 60% | 70% | 10% | 420 | ¥2,058.00 | ¥0.206 |
| 强势 | 70% | 80% | 18% | 1,008 | ¥4,939.20 | ¥0.494 |

这些是规划情景，不是行业平均值。

### 11.3 基准情景下的活动规模

假设：

- 开始率 60%；
- 完成率 70%；
- 支付墙转化率 10%；
- 售价 ¥4.9；
- 支付、退款等合计预留 3%；
- 渠道合作情景按毛收入 30% 分成；
- 固定现金成本 ¥5,000。

| 落地页访客 | 订单 | 毛收入 | 自有流量贡献收入 | 30% 分成流量贡献收入 | 自有流量项目利润 | 分成流量项目利润 |
|---:|---:|---:|---:|---:|---:|---:|
| 10,000 | 420 | ¥2,058 | ¥1,996 | ¥1,379 | -¥3,004 | -¥3,621 |
| 50,000 | 2,100 | ¥10,290 | ¥9,981 | ¥6,894 | ¥4,981 | ¥1,894 |
| 100,000 | 4,200 | ¥20,580 | ¥19,963 | ¥13,789 | ¥14,963 | ¥8,789 |

### 11.4 盈亏平衡流量

在上述基准情景和 ¥5,000 固定成本下：

- 全部为自有流量时，约需 **25,047 个落地页访客**；
- 全部为 30% 分成流量时，约需 **36,262 个落地页访客**。

这说明：

> 4.9 元产品不是“有几千人看看就能赚很多钱”的生意。它需要足够大的低成本流量，或明显高于基准的付费转化率。

### 11.5 最大可承受获客成本

基准情景下，每个落地页访客毛收入约 ¥0.206。扣除支付、退款、税费与运营后，可承受的付费获客成本会更低。

因此：

- 不应在首发阶段购买高于贡献收入/访客的广告流量；
- 自有流量和自然热点价值极高；
- 任何固定 KOL 费用都应换算为预期落地页访客成本；
- 需要以“每千访客贡献毛利”而不是播放量判断渠道。

### 11.6 三个最重要的商业指标

| 指标 | 公式 | 用途 |
|---|---|---|
| 支付墙转化率 | 支付成功人数 / 到达支付墙人数 | 判断用户是否愿意为结果付费 |
| 每千访客毛收入 | 毛收入 / 落地页 UV × 1,000 | 比较不同渠道的商业质量 |
| 每千访客贡献毛利 | 扣除支付、退款和分成后的收入 / UV × 1,000 | 决定是否继续买量或合作 |

## 12. 预算与财务规划

### 12.1 轻量自制预算

| 项目 | 建议现金范围 | 说明 |
|---|---:|---|
| 域名、服务器、存储与监控 | ¥300—¥1,500 | 取决于备案、云服务和流量 |
| 视觉与插画 | ¥0—¥3,000 | 自制可降为零；精美程度直接影响商品感 |
| 前后端开发 | ¥0—¥5,000 | 自研为机会成本；外包则更高 |
| 文案与报告 | ¥0—¥1,500 | 建议核心内容自己掌控 |
| 支付、主体、备案和工具 | 按实际 | 不在未核实前假设固定金额 |
| 内测激励与小额渠道 | ¥500—¥2,000 | 免费码、群红包、小创作者试发 |
| 风险预留 | ¥500—¥1,500 | 退款、修复、临时服务器扩容 |
| **建议首期现金上限** | **¥3,000—¥8,000** | 不含创始人时间成本 |

如果需要完整外包视觉、开发和内容，现金预算可能显著高于该范围。OPC 应优先自制或使用成熟组件，避免为了“精美”而在验证前投入过大。

### 12.2 预算纪律

1. 未打通合法收款前，不投入大额视觉和推广。
2. 未完成 30—50 人内测前，不支付 KOL 坑位费。
3. 未获得至少 1,000 个支付墙 UV 前，不开发小程序。
4. 未证明每千访客贡献毛利为正前，不规模化买量。
5. 首期固定现金投入设上限，超出必须重新评审。

### 12.3 现金流顺序

```text
先确认主体与支付可行
→ 再完成最小内容与原型
→ 小范围内测
→ 正式支付测试
→ 自有流量发布
→ 根据真实收入决定是否追加渠道预算
```

不要反过来先做大规模内容和设计，最后才发现支付或经营主体无法上线。

### 12.4 财务目标

建议把首期目标分成三个层级：

| 层级 | 定义 |
|---|---|
| 技术成功 | 支付、交付、恢复和退款链路稳定，没有重大故障 |
| 商业成功 | 贡献收入覆盖全部外部现金成本 |
| 爆款成功 | 在不显著增加售后与投诉的前提下，流量和订单持续放大，项目利润达到现金投入的 2 倍以上 |

不要求首期形成稳定月收入。

## 13. OPC 运营模式

### 13.1 一人公司的核心职责

| 角色 | 必须完成的工作 |
|---|---|
| 产品 | 控制范围、决定题目、付费墙和报告结构 |
| 内容 | 16 类报告、金句、渠道素材、FAQ |
| 设计 | 视觉规范、人格卡、落地页关键画面 |
| 技术 | 答题、计分、支付、报告、数据和恢复 |
| 运营 | 发布内容、渠道合作、数据复盘 |
| 客服 | 处理看不到报告、重复付款、退款和投诉 |
| 合规 | 审核宣传、隐私、售后、金融边界和平台规则 |

若某些工作外包，创始人仍需保留：

- 核心内容；
- 商业数据；
- 支付账户；
- 域名和源代码权限；
- 用户与订单数据控制权。

### 13.2 每日运营 SOP

上线期每天至少检查：

1. 页面是否能打开；
2. 支付成功率；
3. 付费后报告打开率；
4. 支付回调失败订单；
5. 重复付款；
6. 退款与投诉；
7. 渠道数据；
8. 服务器错误；
9. 社交平台评论中的主要质疑；
10. 当日收入与现金支出。

### 13.3 客服最小配置

- 一个公开客服入口；
- 一个订单查询表单；
- 四类标准处理模板：支付成功未解锁、重复付款、下载失败、退款申请；
- 订单与处理记录；
- 明确的服务时间和预计响应方式；
- 不在客服中回答具体股票和投资建议。

低价不等于不需要售后。5 元订单也可能产生平台投诉和负面传播。

### 15.2 指标看板

| 指标 | 建议首期观察线 | 说明 |

| 落地页开始率 | ≥ 50% | 低于此值先改首屏和价值表达 |
| 测试完成率 | ≥ 65% | 低于此值缩题、改题或修性能 |

### 15.3 实验优先级

只测试高杠杆变量：

1. 首屏标题；
2. 题目数量；
3. 付费墙目录和示例；
4. 价格；
5. 人格主视觉；
6. 结果卡文案。

不要首期测试：

- 复杂推荐算法；
- 会员套餐；
- 社区；
- AI 生成方式；
- 多端同步。

### 15.4 实验纪律

- 每次尽量只改变一个主要变量；
- 至少记录渠道差异；
- 不因为单日偶然波动立即改版；
- 投诉与负面评论与收入同时看；
- 不能只优化付款率而损害信任和交付质量。

## 16. 合规与信任设计

> 本节是商业规划中的风险提示，正式上线前应由熟悉互联网、消费者权益和证券业务边界的专业人士结合实际页面审查。

### 16.1 金融内容边界

中国证监系统公开案例表明，未取得相应资格却向用户提供具体证券品种选择或买卖时机建议，可能构成非法证券投资咨询；相关“荐股软件”案例曾受到行政处罚。[^5] 证监部门也持续提醒投资者核实荐股机构和人员资质。[^6]

TT16 可以输出：

- 你更依赖研究还是市场信号；
- 你在连续亏损后容易增加交易频率；
- 你倾向于集中还是分散；
- 你可以尝试预先写下交易理由；
- 娱乐化人格描述。

TT16 不输出：

- 任何具体股票、基金、期货或虚拟资产推荐；
- 目标价格；
- 买入、卖出或加仓时点；
- 收益率、胜率或“适合赚哪类钱”；
- 个性化资产配置比例；
- “某人格适合重仓科技股”；
- 通过客服、群聊或报告变相荐股。

免责声明不能挽救实际内容越界，因此必须先控制内容，再加免责声明。

### 16.2 娱乐性质说明

所有关键页面应展示：

> TT16 是娱乐性质的交易风格测试，结果仅基于本次自我回答生成，不属于专业心理测评、投资者风险承受能力评估、证券投资咨询或任何买卖建议。投资有风险，决策需独立判断。

### 16.3 个人信息保护

《个人信息保护法》要求个人信息处理具有明确、合理目的并采取最小范围；金融账户属于敏感个人信息，处理敏感个人信息需要更严格的必要性、保护措施和单独同意。[^7]

首期应遵守：

- 不采集姓名、身份证、券商账号、持仓、资金规模和交易流水；
- 默认匿名答题；
- 只收集完成测试、订单交付和统计所必需的数据；
- 把测试答案、设备数据和订单数据分别管理；
- 明示数据用途、保存方式和删除/查询渠道；
- 不把用户答案出售给第三方；
- 渠道合作只提供汇总数据，不提供个人答案；
- 采用访问令牌保护付费报告；
- 对日志、备份和管理后台设置权限。

### 16.4 数字内容与退款

现行网络购物规则对在线下载或拆封的数字化商品设有特殊规定，同时要求经营者对不适用七日无理由退货的商品进行显著标注；地方市场监管部门 2026 年发布的合规指引也强调在提交订单前设置消费者确认。[^8][^9]

TT16 不应简单写“数字商品一律不退”。建议：

- 在付款前展示价格、报告目录、示例、交付方式和售后规则；
- 根据实际交付方式，由专业人士确认是否以及如何设置单独确认；
- 对重复扣款、付款后未交付、报告无法打开、内容严重缺失等情况主动退款或补救；
- 保留退款和纠纷处理记录；
- 不用格式条款排除因自身故障或虚假宣传产生的责任。

### 16.5 宣传合规

禁止使用：

- “科学准确率 98%”；
- “权威心理机构认证”但无真实依据；
- “测完就能提高收益”；
- “最适合你的股票策略”；
- 虚假用户数量；
- 虚构限时优惠；
- 未经许可使用券商、媒体或学校名义背书。

### 16.6 经营、支付和税务

商业上线前应具备：

- 合法经营主体；
- 适配业务类目的支付商户；
- 域名、备案和平台要求；
- 真实经营者名称与联系方式；
- 订单、退款、对账、发票和纳税流程；
- 与渠道方的分成和结算约定。

具体主体形式、税种、发票和支付费率应以所在地政策及服务商审核为准。

### 16.7 品牌与知识产权

上线前完成：

- TT16、TradeType 16 名称检索；
- 商标、域名和社交账号可用性检查；
- 不宣称与 Myers-Briggs、MBTI 官方或任何券商存在关联；
- 人格名称、插画、字体、图标、音乐和素材确保原创或有授权；
- 与外包人员签署著作权和源文件交付约定。

## 17. 主要风险与应对

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 没有流量 | 发布后页面 UV 很低 | 停止优化细枝末节，先解决内容与渠道 |
| 流量有但没人开始 | 开始率低于 35%—50% | 重写首屏，缩短说明，展示人格样例 |
| 做完但不付款 | 支付墙转化低于 5% | 检查收费是否提前告知、报告样例、价格和交付价值 |
| 用户觉得被套路 | 评论集中出现“做完才收费” | 首页显著展示 4.9 元，付费墙展示真实样例 |
| 报告被认为全是废话 | 退款、差评、用户互相比对后发现高度重复 | 提高类型独有内容比例，增加具体交易场景 |
| 免费竞品截流 | 用户直接搜索 GBTI 免费版 | 强化品牌视觉、原创维度、商品样例和内容传播 |
| KOL 合作亏损 | 访问成本高于每访客贡献 | 先分成、后固定；用短链和订单归因 |
| 支付或交付故障 | 支付成功但无法查看 | 主动查询、订单恢复、人工补发、监控告警 |
| 合规投诉 | 用户认为荐股或虚假宣传 | 删除具体标的/收益内容，公开娱乐定位，审查宣传 |
| 隐私问题 | 收集过多身份或交易信息 | 首期匿名、最小收集、不接券商和流水 |
| 抄袭 | 相似页面快速出现 | 接受低壁垒现实，依靠速度、渠道和品牌完成窗口变现 |
| 热点迅速结束 | 流量连续下降 | 停止追加开发，保留自动销售或直接归档 |

## 18. 决策门槛：继续、调整还是停止

### 18.1 上线前 Go 条件

以下条件缺一项都不应大规模发布：

- 20 题和计分规则完整；
- 16 类结果均已人工检查；
- 首页提前披露 4.9 元；
- 真实支付、回调、恢复和退款测试通过；
- 至少 30 名内测用户走完全链路；
- 不存在具体荐股或收益承诺；
- 隐私、用户协议、售后规则和联系方式上线；
- 有至少一个可产生真实访问的渠道计划；
- 服务器和监控能够应对短时流量波动。

### 18.2 数据决策矩阵

| 状态 | 数据表现 | 决策 |
|---|---|---|
| 停止 | 有效流量仍很少，且没有可行渠道 | 不继续加功能，归档项目 |
| 停止 | 累计 5,000 个支付墙 UV 后支付率仍 < 3%，两次主要调整无改善 | 停止商业化或改为免费活动 |
| 调整 | 支付率 3%—8%，但用户认可内容 | 优化付费墙、价格、样例和题目长度 |
| 调整 | 支付率高但退款/投诉 > 5% | 暂停放量，优先修报告和交付 |
| 继续 | 支付率 ≥ 8%，退款和投诉可控，贡献收入为正 | 继续自有流量与小型渠道合作 |
| 放大 | 每千访客贡献稳定、渠道成本低于贡献、技术链路稳定 | 增加内容产量和可控渠道预算 |

上述百分比是内部管理阈值，不是行业标准。

### 18.3 项目结束标准

满足任一情况可以主动结束：

- 流量窗口消失；
- 继续维护的时间价值高于预期新增利润；
- 已达到预设现金回报；
- 渠道成本持续上升；
- 合规或平台成本超过业务价值；
- 创始人有更高回报的下一项目。

接受结束，是快消品模式的组成部分。

## 19. 与现有 PRD 的关系及必须修改项

现有《TT16 PRD v1.0》以“免费 32 题、先验证完成与分享”为核心。当前商业决策已经改变，因此开发前必须生成 PRD v1.1，并至少修改以下内容：

| 原 PRD v1.0 | 商业化 PRD v1.1 |
|---|---|
| 32 道基础题 | 20 道商业化题目 |
| 结果免费展示 | 四字母、名称、分数和正文全部付费锁定 |
| MVP 不付费 | P0 接入订单、支付、回调、退款与恢复 |
| 以有效结果查看为北极星 | 以每千访客贡献毛利为北极星 |
| 六个完整风险徽章 | 首期可缩为两个压力场景模块 |
| 分享卡面向所有结果用户 | 仅付费用户生成结果卡；未付费用户生成邀请卡 |
| 不强调经营主体 | 主体、备案、支付与售后变为上线前置条件 |
| 5—7 分钟 | 目标 3—5 分钟 |

建议把本商业规划书作为 PRD v1.1 的商业输入，而不是在旧 PRD 上直接开发。

## 20. 可选的后续复制，而非平台化

TT16 成功后，最自然的扩展不是会员和社区，而是复制同一套底层，开发新的低价测试商品，例如：

- 基金定投人格；
- 消费人格；
- 职场决策人格；
- 恋爱花钱人格；
- 大学生生存人格；
- AI 使用人格。

复制条件：

1. TT16 已覆盖现金成本；
2. 支付与报告系统可复用；
3. 至少一个渠道能稳定带来低成本流量；
4. 用户对报告价值没有大面积负面反馈。

这样，OPC 真正积累的是“低价互动数字商品工厂”，而不是被迫维护一个交易社区。

## 21. 最终建议

TT16 当前最适合的形态是：

> **一个移动端 H5 + 20 道题 + 明示价格的 4.9 元硬付费墙 + 16 份模块化报告 + 在线结果 + PDF/长图 + 分享卡。**

商业上必须同时接受三件事：

1. 它可以赚钱，但收入高度依赖低成本流量；
2. 它可能只火几周，不会自然变成长期公司；
3. 4.9 元不代表用户不在意质量和售后。

最值得坚持的不是复杂产品愿景，而是以下纪律：

- 先解决支付和渠道，再投入美术；
- 价格提前说清楚；
- 报告可以模板化，但不能明显敷衍；
- 不碰荐股和收益承诺；
- 用贡献毛利判断渠道；
- 数据不好时及时停止；
- 数据好时也只放大已经验证的链路，不顺势增加无关功能。

在 OPC 早期，这是一条合理、清晰且可控的商业路线。

# 附录 F：简易财务计算器

```text
输入：
V = 落地页访客
S = 开始率
C = 完成率
P = 支付墙转化率
A = 客单价
F = 支付与退款等比例
R = 渠道分成比例
K = 固定现金成本

订单 = V × S × C × P
毛收入 = 订单 × A
贡献收入 ≈ 毛收入 × (1 - F - R)
项目利润 ≈ 贡献收入 - K

最大可接受访客成本 ≈ 贡献收入 / V
```
