## 0. 核心结论

TT16 的商业目标不是打造长期留存平台，而是在一个有限流量窗口中验证：

> **完成测试的用户，是否愿意支付 4.9 元，获得一个明确、精美、具体且可分享的交易人格报告。**

当前已经完成高保真免费 Demo、32 题模型、16 型内容和视觉资产；尚未完成 20 题商业模型、付费墙、订单支付、购买权益、数据归因、合规页面和真实付费验证。

因此当前执行重点为：

1. 先确认经营主体、支付和备案路线；
2. 冻结商业化 PRD v1.1 和 20 题模型；
3. 打通订单—支付—权益—报告—恢复—退款闭环；
4. 完成数据、合规、监控和客服；
5. 经过 30—50 人全链路内测后再软发布；
6. 只在贡献收入和用户信任同时成立时放量。

| 决策项 | v1.1 选择 | 明确不做 |

## 3. 用户、场景与价值主张

### 3.1 核心用户

- 经常在社交平台、群聊或社区表达投资观点的成年用户；
- 入市时间不长、正在形成方法的新手投资者；
- 喜欢人格、财经梗和身份标签的年轻财经内容用户；
- 经历亏损、踏空、卖飞或追高，希望解释行为的用户。

### 3.2 非目标用户

- 未满 18 岁用户；
- 寻找具体股票、买卖时点或仓位建议的人；
- 需要正式心理诊断或风险承受能力评估的人；
- 专业机构交易、量化或资产配置团队。

### 3.3 Jobs to Be Done

> 当我看到一个和真实交易经历有关的人格测试时，我希望在几分钟内知道自己的交易人格，并看到几句能解释过去行为的具体描述，以满足好奇、确认自我并与朋友分享。

### 3.4 价值主张

用户支付 4.9 元购买的不是投资建议，而是：

1. 一个明确的四字母人格身份；
2. 一份交易语境具体、不同类型可辨的行为报告；
3. 一张愿意保存和分享的视觉卡片；
4. 一次即时、低决策成本的好奇闭环。

### 3.5 品牌承诺

> 花 4.9 元，立即获得一个明确的人格身份、一份看得懂的交易行为报告和一张值得保存的结果卡。

不承诺盈利、胜率、策略、股票选择、风险等级或心理诊断。

## 4. 商品定义

### 4.1 唯一 SKU

| 商品 | 价格 | 核心交付 | 权益 |
|---|---:|---|---|
| TT16 完整交易人格报告 | ¥4.9 | 人格代码与称号、四维分数、完整在线报告、分享卡 | 当前报告永久查看；不自动续费 |

PDF/长图在不阻塞首笔订单的前提下作为 P1；若首页承诺提供，则必须在收费前完成。

### 4.2 付费报告内容

每份报告应包含：

1. 人格代码、名称、主视觉和一句话；
2. 四维分数和解释；
3. 典型决策路径；
4. 暴跌、踏空和连续盈利时的行为；
5. 3 个优势和 3 个高频 Bug；
6. 压力下的人格变形；
7. 3—5 条可执行但非个性化投资建议的自我检查；
8. 结果卡、免责声明和保存/分享入口。

### 4.3 内容质量底线

- 每型至少 50% 内容为类型独有；
- 至少 3 个具体交易行为描述；
- 互换两个人格正文后应明显不匹配；
- 不使用“有时果断、有时犹豫”式万能句作为主体；
- 行为建议只谈记录、复核、边界和过程，不给具体资产建议；
- 内容版本随已购 report snapshot 固定。

## 5. 商业用户链路

```text
渠道内容 / 朋友分享
→ 商业落地页：提前显示 ¥4.9
→ 创建匿名会话
→ 完成 20 题
→ 服务端评分与生成 3—5 秒
→ 付费墙：只显示报告已生成、目录、样例和交付说明
→ 创建订单并支付
→ 回调 / 主动查询确认
→ 发放报告权益与访问 token
→ 完整报告
→ 保存卡片 / PDF / 长图
→ 分享与回流
```

### 5.1 首页信任要求

首屏必须包含：

- “20 道真实交易情境”；
- “约 3—5 分钟”；
- “测试免费完成”；
- “完整结果与报告 ¥4.9”；
- “一次购买，不自动续费”；
- 娱乐性质和非投资建议简短说明。

### 5.2 付费墙原则

可以展示：

- 报告已生成；
- 模糊轮廓；
- 报告目录；
- 与用户无关的真实样例；
- 价格、交付、售后和免责声明。

不可以展示或下发：

- 用户四字母代码；
- 用户人格名称；
- 用户四维分数；
- 可还原用户类型的字段；
- 完整报告正文或结果卡。

### 5.3 反套路设计

- 价格必须在答题前出现；
- 样例必须是真实商品质量，不用虚假评价；
- 不使用虚假倒计时、虚构销量和永久折扣；
- 付款前清楚说明交付与退款规则；
- 付款失败或取消后保留测试结果和恢复入口。

## 6. 20 题模型迁移

### 6.1 结构

| 类型 | 数量 | 作用 |
|---|---:|---|
| 四维核心题 | 16 | 每个维度 4 题，生成四字母代码 |
| 压力题 | 2 | 暴跌、踏空/连续盈利内容模块 |
| 一致性题 | 2 | 检查明显矛盾和随意作答 |
| 合计 | 20 | 目标 3—5 分钟 |

### 6.2 迁移原则

- 从现有 24 道维度题中按场景覆盖、区分度、长度和方向平衡选择；
- 每个维度至少有 1 道反向或不同语境题；
- 重新定义最低有效答案、质量等级和边界区间；
- 不能沿用“至少 26 题”与 32 题覆盖率阈值；
- 保留 32 题 Demo 作为研究参考，不与商业结果混用；
- 题库、评分和报告内容分别版本化。

### 6.3 验证

- 单元测试覆盖 16 类型、平分、边界、缺失、无效值、反向题和一致性；
- 选取至少 30 组答题，比较 32 题与 20 题类型和维度方向；
- 8—12 人可用性测试验证理解与完成时间；
- 30—50 人内测观察类型分布是否异常集中；
- 不宣传科学信效度或准确率。

## 7. 最小技术与交付架构

```text
移动端 H5
├── 商业落地页 / 样例
├── 20 题答题
├── 生成态 / 付费墙
├── 订单与支付状态
├── 完整报告
└── 分享卡 / PDF 或长图

轻后端
├── 匿名 session
├── 服务端计分与报告快照
├── 商品与订单
├── 支付回调、验签、幂等、主动查询
├── entitlement 与 report token
├── 恢复、退款和对账
├── 事件采集与渠道归因
└── 运营查询与基础看板
```

### 7.1 核心数据实体

| 实体 | 关键字段 |
|---|---|
| assessment_session | id、题库版本、渠道、状态、创建/完成时间 |
| answer | session_id、question_id、value、answered_at |
| assessment_result | session_id、评分版本、type_code、维度、质量、内容版本 |
| report_snapshot | result_id、完整内容快照、生成时间 |
| product | sku、价格、币种、状态、交付版本 |
| order | id、session_id、金额、渠道、状态、支付方式、时间 |
| payment_attempt | order_id、provider_id、状态、回调摘要、重试信息 |
| entitlement | order_id、report_id、状态、发放/撤销时间 |
| report_token | entitlement_id、token_hash、有效状态、最近使用时间 |
| event | session_id、匿名访客、事件名、版本、渠道、时间 |
| support_case | order_id、类型、状态、处理结果、时间 |

### 7.2 订单状态

```text
created → payment_pending → paid → fulfilled
                  ↘ failed / cancelled / expired
paid / fulfilled → refund_pending → refunded
```

- 金额和 SKU 由服务端决定；
- 回调必须验签并幂等；
- 回调未到时允许主动查询；
- 多次回调只发放一次权益；
- 支付成功但交付失败进入告警和补偿队列；
- 退款后按公开规则决定是否撤销访问。

### 7.3 权益和访问

- 报告 URL 使用高熵随机 token，不使用可枚举 ID；
- 数据库存储 token hash；
- 完整结果不出现在付费前接口响应、HTML 或静态包；
- report snapshot 保证已购内容稳定；
- 支持当前设备恢复、订单号恢复和客服恢复；
- 逐题答案不进入分享卡和公开报告链接。

## 8. 数据与实验

### 8.1 北极星

> **每 1,000 个落地页访客产生的贡献收入。**

### 8.2 关键指标

| 指标 | 内部观察线 | 作用 |
|---|---:|---|
| 落地页开始率 | ≥ 50% | 判断首屏价值表达 |
| 测试完成率 | ≥ 65% | 判断题目和体验 |
| 支付墙转化率 | ≥ 8% | 判断核心付费假设 |
| 付费后报告打开率 | ≥ 97% | 判断交付可靠性 |
| 退款/主动投诉率 | < 3% | 判断商品质量与信任 |
| 付费用户分享点击率 | ≥ 15% | 判断结果卡传播价值 |
| 技术失败率 | < 0.5% | 判断链路可靠性 |

以上为内部门槛，不是行业标准。

### 8.3 必需事件

`landing_view`、`test_start`、`question_answer`、`test_complete`、`paywall_view`、`payment_start`、`payment_success`、`report_view`、`card_generate`、`share_click`、`refund_request`、`delivery_error`。

所有事件至少携带：渠道、页面版本、题库版本、价格版本、付费墙版本、报告版本、匿名 session 和时间；不得在分析事件中上传逐题原文或支付敏感信息。

### 8.4 实验卡

每次实验必须记录：

- 假设；
- 唯一主要变量；
- 主指标；
- 退款、投诉和完成率等护栏；
- 渠道与版本；
- 期望改善幅度；
- 最小样本或最长运行时间；
- 继续、回滚或不下结论规则。

500 个支付墙 UV 的价格测试只能作为方向性证据；渠道混杂时不得直接下结论。

## 9. 流量与发布

### 9.1 渠道顺序

1. 自有内容与朋友圈；
2. 真实投资社群与朋友群；
3. 小型财经或生活方式创作者分成；
4. 校园金融社团和模拟炒股群；
5. 数据成立后的低额渠道测试；
6. 单位经济稳定后再考虑固定费用或信息流。

### 9.2 首发素材包

软发布前至少准备：

- 4 张代表人格卡；
- 10 条可直接发布的图文/短视频脚本；
- 3 组“同一场景，16 型不同反应”内容；
- 价格、隐私、退款和科学性质 FAQ；
- 评论区标准回复；
- 每个渠道独立短链或 creator code；
- 合作方可用的素材授权说明。

### 9.3 自然裂变假设

硬付费墙会削弱免费结果传播，因此增长模型不能假设自动裂变。需要同时依赖：

- 外部持续内容；
- 付费用户结果卡；
- 未付费邀请卡；
- 创作者联名；
- 可追踪回流链接。

## 10. 单位经济

### 10.1 公式

```text
订单数 = 落地页 UV × 开始率 × 完成率 × 支付墙转化率
毛收入 = 订单数 × 实收客单价

可变成本 = 支付比例费
         + 支付固定费
         + 退款损失
         + 渠道分成
         + 税费
         + 发票与结算相关成本
         + 按量云服务成本

贡献收入 = 毛收入 - 可变成本
项目利润 = 贡献收入 - 固定现金成本
每千访客贡献收入 = 贡献收入 ÷ 落地页 UV × 1,000
```

### 10.2 规划情景

价格 ¥4.9 时：

| 情景 | 开始率 | 完成率 | 支付率 | 每万 UV 订单 | 毛收入 |
|---|---:|---:|---:|---:|---:|
| 保守 | 45% | 60% | 5% | 135 | ¥661.50 |
| 基准 | 60% | 70% | 10% | 420 | ¥2,058.00 |
| 强势 | 70% | 80% | 18% | 1,008 | ¥4,939.20 |

这些数字只是内部假设。正式预算必须把支付固定费用、税费、退款、分成和开票成本逐项填入，不能只用统一 3% 代替。

### 10.3 预算纪律

- G0 未通过前不投入大额视觉或渠道费用；
- 30—50 人内测前不付高额 KOL 坑位费；
- 1,000 个支付墙 UV 前不开发小程序；
- 每千访客贡献收入未转正前不规模买量；
- 首期现金上限建议 ¥3,000—¥8,000，超出必须重新评审；
- 创始人时间单独记录，但不伪装成零成本。

## 11. 合规、隐私与信任

v1.0 第 16 节及其参考资料继续有效。执行层必须补齐以下可交付材料：

- 隐私政策；
- 用户协议；
- 商品、交付和永久查看含义；
- 退款与售后规则；
- 经营者名称、联系方式、客服时间；
- 未成年人限制；
- 数据查询、更正、删除和撤回渠道；
- 支付前必要确认；
- 素材、字体、插画和外包著作权记录；
- TT16 / TradeType 16 名称、域名和商标检索记录；
- 上线前金融内容与广告文案审查记录。

### 11.1 数据最小化

- 默认匿名；
- 不采集券商账号、持仓、资金规模、交易流水和身份证；
- 答案、订单和分析数据按用途分离；
- 金融账户或支付敏感信息不进入 TT16 数据库；
- 日志脱敏并设置保留周期；
- 渠道方只获得汇总数据；
- 分享不包含逐题答案和用户标识。

### 11.2 内容边界

允许：描述研究/信号、持有/交易、防守/进攻、计划/灵活等行为倾向。

禁止：具体证券、目标价、买卖时点、收益或胜率承诺、个性化仓位、人格对应行业/股票推荐，以及客服中的变相荐股。

## 12. 运营、客服与停运

### 12.1 每日上线检查

- 页面与支付可用性；
- 支付成功率和回调失败；
- 报告打开率和交付失败；
- 重复付款、退款和投诉；
- 渠道数据、收入和成本；
- 服务端错误、延迟和存储；
- 社交评论中的主要质疑。

### 12.2 客服最小能力

- 公开客服入口和服务时间；
- 订单查询表单；
- 支付成功未解锁、重复付款、下载失败、退款申请四类模板；
- 工单状态、证据和处理记录；
- 超过权限的问题升级给负责人；
- 不回答具体股票和投资建议。

### 12.3 停运方案

项目结束前必须决定：

- 已购报告继续访问多久以及如何导出；
- 退款和客服窗口；
- 新订单关闭时间；
- 用户通知方式；
- 数据保留与删除；
- 域名、支付、数据库和监控下线；
- 订单、税务、合同和渠道结算归档。

快闪商品可以结束，但不能让已付款用户突然失去交付。

## 14. 决策与责任机制

即使是一人公司，也要为每个工作域指定 DRI，允许同一人兼任。

| 工作域 | DRI | 关键决策 | 完成证据 |

| 内容/模型 | 待填 | 20 题、评分、报告 | 版本化题库、测试、内容 QA |

| 合规/客服 | 待填 | 政策、退款、内容边界 | 审查记录和 SOP |
| 增长 | 待填 | 渠道、素材、实验 | 可追踪链接与实验卡 |

决策记录至少包含：日期、问题、备选方案、决定、原因、复查条件和责任人。

## 15. 继续、调整与停止

| 状态 | 数据或事实 | 行动 |
|---|---|---|
| 停止商业开发 | G0 无可行主体/支付/备案路线 | 保留免费 Demo 或归档 |
| 停止 | 累计 5,000 支付墙 UV 后支付率仍 <3%，两次主要调整无改善 | 关闭收费或转免费活动 |
| 调整 | 支付率 3%—8%，内容评价尚可 | 优化样例、付费墙、价格和题量 |
| 暂停放量 | 支付率高但退款/投诉 >5% | 先修商品、交付和信任 |
| 继续 | 支付率 ≥8%，贡献为正，退款投诉可控 | 继续自有流量与小合作 |
| 放大 | 渠道成本低于贡献，数据和技术可信 | 增加内容与可控渠道预算 |

项目也可因热点结束、维护时间价值过高、合规成本过高或达到预设回报而主动结束。
