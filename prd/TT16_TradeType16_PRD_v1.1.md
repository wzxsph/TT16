## 1. 产品摘要

TT16 是一款面向 18 岁以上中文财经内容用户的娱乐型交易行为人格测试。用户免费完成 20 道场景题，结果生成后支付 ¥4.9 一次性解锁四字母人格、完整在线报告和分享卡。

### 1.1 本版本唯一商业问题

> 完成测试的用户是否愿意支付 4.9 元，获得自己的 TT16 人格身份与完整报告？

### 1.2 核心约束

- 价格在答题前显著可见；
- 未付费用户不能从前端资源或接口还原完整结果；
- 支付成功后立即可靠交付；
- 不连接券商账户，不采集持仓和资金信息；
- 不提供具体证券、买卖时点、收益或仓位建议；
- 不使用个人收款码替代正式订单支付；
- 不做订阅、社区、小程序、App 或 AI 自由生成报告。

## 3. 用户与关键场景

### 3.1 主要用户

- 社交型股民；
- 新手投资者；
- 年轻财经内容用户；
- 经历亏损、踏空或追高，希望解释行为的用户。

### 3.2 核心场景

1. 从社交内容进入，理解价格后开始测试；
2. 3—5 分钟完成答题，到达报告已生成的付费墙；
3. 支付后立即查看报告；
4. 保存或分享结果卡；
5. 回调延迟、刷新、换浏览器或清缓存后恢复报告；
6. 重复付款、下载失败或要求退款时获得客服处理。

## 7. 主流程

### 7.1 首次购买

```text
landing_view
→ 用户看到价格与交付
→ test_start / 创建 session
→ 20 题
→ complete / 服务端质量检查
→ 如质量不足：免费复核或重测
→ 服务端生成并保存 result + report_snapshot
→ 前端只收到 paywall payload
→ 创建 order
→ payment_start
→ 支付回调或主动查询确认 paid
→ 发放 entitlement + report token
→ fulfillment
→ report_view
→ 保存/分享
```

### 7.2 支付处理中

- 订单页展示“处理中”，不重复创建订单；
- 前端轮询订单状态，退避并设置上限；
- 超时后提供“重新查询支付结果”；
- 回调晚到时自动完成权益；
- 用户关闭页面后可通过本地恢复键或订单号继续查询。

### 7.3 报告恢复

优先顺序：

1. 本设备保存的恢复凭证；
2. 原报告 token；
3. 订单号 + 支付服务允许核验的信息；
4. 客服按支付交易记录人工恢复。

恢复流程不得公开逐题答案，不得允许枚举订单或报告。

### 7.4 退款

- 用户查看公开售后规则；
- 提交订单号和原因；
- 系统识别重复付款、未交付或技术故障；
- 进入 `refund_pending`；
- 支付服务确认后进入 `refunded`；
- 保留操作审计；
- 报告访问是否撤销由公开规则决定，不在前端临时变化。

## 9. 20 题和评分规格

### 9.1 题型

```text
Q01–Q16：四维题，每维 4 题
Q17–Q18：压力场景
Q19–Q20：一致性题
```

核心题使用 5 档答案：`-2, -1, 0, 1, 2`；压力题可增加“未经历”；一致性题不直接决定类型。

### 9.2 维度计分

对每个核心题：

```text
item_score = answer_value × direction × weight
dimension_raw = Σ item_score
dimension_max = Σ (2 × weight)
right_ratio = (dimension_raw + dimension_max) / (2 × dimension_max)
right_percent = round(right_ratio × 100)
left_percent = 100 - right_percent
```

暂定边界区间为 48%—52%，必须由内测分布复核。

### 9.3 类型代码

- RS：左为 R，右为 S；
- HT：左为 H，右为 T；
- DA：左为 D，右为 A；
- PF：左为 P，右为 F。

正好 50% 时使用版本化 tie-break：优先检查该维度的高区分题；仍相同时使用固定默认侧，并标记 boundary。不得随机生成类型。

### 9.4 完整性和质量

- 16 道核心题全部需要有效答案；
- 压力题允许“未经历”，使用通用内容回退；
- 一致性题必须回答；
- 明显矛盾、极短完成时间或机械同值进入复核提示；
- 质量不足时允许免费复查相关题或重测；
- 质量标签用于解释，不得宣传为心理测量信度。

### 9.5 迁移验收

- 16 个类型固定样例；
- 两端极值、全中性、边界、反向、缺失和非法值；
- 30 组 32 题/20 题对照；
- 20 题类型分布和各维度均值检查；
- 平均完成 3—5 分钟；
- 题库、评分和报告版本进入结果记录。

## 11. API 边界

以下为逻辑边界，具体路径可随技术实现调整，但权限和最小响应原则不可删除。

| 方法 | 路径 | 用途 | 关键响应 |
|---|---|---|---|
| POST | `/v1/sessions` | 创建匿名测试会话 | session_id、恢复凭证、题库版本 |
| GET | `/v1/sessions/{id}` | 恢复状态 | 当前题号、已答题号，不返回答案原文 |
| PUT | `/v1/sessions/{id}/answers/{qid}` | 保存答案 | 版本、保存时间 |
| POST | `/v1/sessions/{id}/complete` | 评分、质量门、报告快照 | paywall payload 或复核要求 |
| POST | `/v1/orders` | 创建商品订单 | order_id、金额、支付参数 |
| GET | `/v1/orders/{id}` | 查询支付和交付状态 | 状态、恢复动作 |
| POST | `/v1/payments/webhook` | 支付服务回调 | 仅服务端使用，验签幂等 |
| POST | `/v1/orders/{id}/query` | 主动查询支付 | 权威订单状态 |
| POST | `/v1/orders/{id}/refund-request` | 发起退款请求 | case_id、状态 |
| POST | `/v1/reports/recover` | 恢复已购报告 | 防枚举统一响应 |
| GET | `/v1/reports/{token}` | 访问付费报告 | 受 entitlement 控制的 snapshot |
| POST | `/v1/reports/{token}/share` | 创建公开分享入口 | share_token，不返回 report_token |
| POST | `/v1/feedback` | 匿名结果反馈 | accepted |
| POST | `/v1/events` | 批量事件 | accepted / rejected counts |

### 11.1 错误契约

错误响应包括稳定错误码、用户可读文案和 request_id；不得返回堆栈、支付敏感字段、完整答案或内部 SQL/存储路径。

## 12. 数据实体与状态机

### 12.1 必需实体

- `assessment_session`；
- `answer`；
- `assessment_result`；
- `report_snapshot`；
- `product`；
- `order`；
- `payment_attempt`；
- `entitlement`；
- `report_token`；
- `share_token`；
- `event`；
- `support_case`；
- `refund`。

### 12.2 订单状态

`created → payment_pending → paid → fulfilled`，异常进入 `failed / cancelled / expired`，退款进入 `refund_pending → refunded / refund_failed`。

### 12.3 会话状态

`started → in_progress → completed → paywalled → purchased`；质量不足可进入 `needs_review`，超时进入 `expired`，但已购报告不随 session 过期。

### 12.4 数据保留

正式期限在上线前由业务必要性和专业审查确定。系统必须支持：

- 分实体设置期限；
- 删除/匿名化；
- 日志和备份同步策略；
- 已购交付、账务和法定义务的例外记录；
- 数据权利请求审计。

## 13. 埋点与数据字典

| 事件 | 必需字段 |
|---|---|
| landing_view | visitor_id、channel、page_version、device、referrer |
| test_start | session_id、questionnaire_version、channel |
| question_answer | session_id、question_id、position、duration、answer_state |
| test_complete | session_id、duration、quality、scoring_version |
| paywall_view | session_id、price_version、paywall_version、channel |
| payment_start | order_id、provider、amount、channel |
| payment_success | order_id、amount、confirmation_source、latency |
| report_view | entitlement_id、report_version、load_status |
| card_generate | entitlement_id、format、result |
| share_click | share_token、channel、target |
| refund_request | order_id、reason_code、source |
| delivery_error | order_id、stage、error_code、request_id |

### 13.1 口径规则

- UV、session、order 和 payment 各有独立 ID，不混用；
- 事件至少一次传输时，服务端按 event_id 去重；
- 测试环境、内部流量和退款订单可过滤；
- 收入以支付/对账数据为准，不以 `payment_success` 前端事件为准；
- 完整人格可用于服务端聚合，但付费前分析响应不得泄露给客户端；
- 分享点击不等于实际发布成功。

## 14. 非功能要求

### 14.1 性能

- 落地页首屏在主流移动网络下可交互目标 ≤ 3 秒；
- 答题切换感知延迟 ≤ 300 毫秒；
- 非支付 API p95 ≤ 800 毫秒；
- 订单查询 p95 ≤ 1.5 秒，不含支付方延迟；
- 报告页面稳定加载，不依赖实时大模型；
- 图片采用 WebP/AVIF 等合理格式和缓存。

### 14.2 可用性与兼容

- 支持主流 iOS Safari、Android Chrome、微信内置浏览器和常见中文应用 WebView；
- 支持刷新、后退、弱网和横竖屏；
- 键盘操作和可见焦点不退化；
- 文本缩放、对比度和减少动画设置可用；
- 不把颜色作为唯一状态表达。

### 14.3 安全

- 全站 HTTPS；
- 服务端金额校验；
- 支付回调验签、重放防护和幂等；
- token 高熵、存 hash、可撤销；
- 输入校验、限流和跨 session 授权；
- 密钥不进入前端、仓库和日志；
- 最小权限、环境隔离和审计日志；
- 备份恢复、发布回滚和依赖漏洞检查；
- CSP、点击劫持、类型嗅探和权限策略等响应头。

### 14.4 可观测性

- API 错误率和 p95；
- 支付发起/成功/回调延迟；
- paid 未 fulfilled 数量；
- 回调验签失败和重试；
- 报告访问失败；
- 数据库容量和备份；
- 告警通知、负责人和升级规则。

## 15. 隐私、合规与信任

### 15.1 页面要求

- 关键页面展示娱乐性质和非投资建议；
- 付费前显示价格、交付、售后和经营信息；
- 明示数据用途、保存、共享和用户权利；
- 明确不采集券商、持仓、交易流水和资金规模；
- 明确 18 岁以上使用；
- TT16 与 MBTI、Myers-Briggs 和券商无关联；
- 不宣传科学准确率、官方认证、收益改善或最佳策略。

### 15.2 正式材料

- 隐私政策；
- 用户协议；
- 商品与交付说明；
- 数字内容与退款/售后规则；
- 经营者信息和客服；
- 必要的支付前确认；
- 素材授权和品牌检索记录；
- 上线前专业审查记录。
