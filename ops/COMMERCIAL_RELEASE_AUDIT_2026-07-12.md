## 1. 判定规则

- **已证明**：当前代码、自动测试、浏览器运行结果或数据库记录直接证明要求成立；
- **部分完成**：沙盒或技术结构成立，但要求范围还包括真实支付、生产环境或人工运营证据；
- **未完成**：当前状态直接表明要求尚未实现；
- **外部证据缺失**：需要经营主体、商户、域名、专业审查或真实用户测试，不能由代码生成。

“没有发现问题”不等于已证明；本地 mock 支付不作为真实支付、退款、对账或合规上线的证据。

## 8. 继续实施所需输入

以下信息缺失会改变真实支付和法律实现，不能由工程侧擅自假设：

1. 经营主体类型和可公开名称；
2. 已开通的支付产品：微信支付、支付宝或聚合服务商，以及具体产品形态；
3. 正式 HTTPS 域名和备案计划；
4. 客服渠道、服务时间和负责人；
5. 数据保留期限与退款后报告访问规则的正式确认；
6. 支付商户后台提供的非秘密标识。密钥、证书私钥和 API Secret 必须放入 Cloudflare Secrets，不得粘贴到聊天、代码或 Git。

取得上述输入后，下一阶段才能实现真实 adapter、回调验签、主动查询、真实退款、对账、远端监控、政策落版和 30—50 人内测。
